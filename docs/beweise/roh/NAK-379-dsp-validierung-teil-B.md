## DSP-16 — M/S-Wortwahl

1. **Quelle.** Entwurf `:2657-2658` steht in §40.1 „Stereo- und Phasenanalyse" (STFT-Analyse des Workers), nicht im DSP-Kern: „M/S wird energienormiert als `M=(L+R)/√2`, `S=(L−R)/√2` berechnet." Für den Kern gelten `:2985` (§44.2) „Stereo-, L/R- und M/S-Matrix mit normalisierter Energie" (ohne Formel) und M-30 (`SONDE-015.md:1078`) „Die M/S-Matrix arbeitet mit normalisierter Energie". Code `DspKern.cpp:998-999`, `:1009` (M/S-Stufe) sowie `:811-812`, `:913-914` (Bänder): M = (L+R)/2, S = (L−R)/2, L = M + S — amplitudennormiert (Rückweg 1), nicht energienormiert (M² + S² = (L² + R²)/2). „neu" stimmt.
2. **Formel und Zahl.** `v6` (K12) prüft beide Konventionen am Rauschen richtig. Eigene Rechnung von Hand: L = R = x ergibt im Code M = x, Mid-Detektorleistung x² gleich der Stereo-Detektorleistung nach E-5 ((d0² + d1²)/2, `DspKern.cpp:842`), also 0 dB; mit /√2 wäre M = √2·x, +3,01 dB. In linearen Stufen (Width, Mono-Bass-Hochpass auf S, statische M/S-Bänder) kürzt sich die Skalierung, der Ausgang ist identisch.
3. **Zusagenlage.** §44.2 `:2985` und M-30 sagen „normalisierte Energie", der Code rechnet amplitudennormiert. Hörbar wäre die Wahl nur an der Detektorschwelle dynamischer Mid/Side-Bänder, und dort ist die gebaute Wahl die konsistente (E-5). Keine hörbare Zusage bricht, DOKU richtig; die Formelzitate des Berichts gehören zur Analyse (§40.1), nicht zum Kern.
4. **Urteil: PRÄZISIERT.** Klasse DOKU. Wirkung: keine (Bericht „–" richtig). Heute erreichbar: entfällt. Planort: Widerspruchszeile; §44.2 `:2985`, SONDE-015 `:1015` und M-30 `:1078` auf „amplitudennormiert, M = (L+R)/2, S = (L−R)/2, L = M + S" berichtigen (das Entwurfszitat `SONDE-015.md:215` folgt dem Entwurf); Code bleibt.
